## Why codes exist

A design code captures decades of experience, including the lessons of past failures, as a set of minimum requirements. Following the code does not guarantee a good pipeline, but departing from it without a sound reason almost guarantees trouble.

## The hierarchy

Documents apply in layers. When they conflict, the higher layer wins, and the stricter requirement is normally applied.

1. **Law and regulation** of the country (for example 49 CFR 192 and 195 in the United States).
2. **Design code** chosen for the pipeline (ASME B31.4, B31.8, ISO 13623 and others).
3. **Company engineering standards** (for example the Saudi Aramco SAES series), which add to or tighten the code.
4. **Project specifications and drawings**, written for one project.
5. **Referenced specialist standards** for materials, welding, coating, testing and so on.

A useful first question on any project: **is the fluid a liquid or a gas at pipeline conditions?** That usually decides between B31.4 and B31.8. Multiphase lines are assigned by the company standard.

<Callout type="note">
Plant piping inside a facility fence is designed to **ASME B31.3**, which has different allowable stresses and rules. The boundary between pipeline code and plant code, usually at the scraper trap or the first isolation valve, must be defined on every project.
</Callout>

<Callout type="aramco">
Saudi Aramco's SAES-L-100 lists the codes that apply to each piping and pipeline system. The SAES-L-400 series then covers cross-country pipelines: L-410 design, L-420 scraper traps, L-440 anchors, L-450 construction and L-460 crossings. Other disciplines add their own: SAES-B-064 for pipeline safety and location class, SAES-H for coatings, SAES-X for cathodic protection, SAES-W for welding and SAES-A-004 for pressure testing. Materials are bought to SAMSS specifications. These numbers are from general knowledge: confirm them against the current index.

## Using a code well

- Read the **scope** first. Many disputes come from applying a code outside it.
- Note the **edition**. Requirements change, and a project is tied to the edition in its contract.
- "Shall" is mandatory, "should" is a recommendation, "may" is a permission.
- A code gives minimums. Good engineering often goes beyond them where the risk justifies it.
